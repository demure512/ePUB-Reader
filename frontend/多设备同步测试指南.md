# 多设备同步功能测试指南

## 🚀 功能概述

本项目已实现多设备数据同步功能，支持以下数据的云端同步：
- 用户个人设置（字体大小、主题、阅读模式等）
- 阅读进度（位置、章节、页码等）
- 书籍管理数据

## 📋 测试前准备

### 1. 数据库初始化
执行数据库初始化脚本：
```sql
-- 在MySQL中执行
source backend/src/main/resources/init-sync-tables.sql;
```

### 2. 启动服务
```bash
# 启动后端服务
cd backend
mvn spring-boot:run

# 启动前端服务
cd frontend
npm run dev
```

## 🧪 测试场景

### 场景1：用户设置同步测试

**步骤：**
1. 在设备A（浏览器1）登录用户账号
2. 修改阅读设置：
   - 调整字体大小
   - 切换主题
   - 修改其他设置
3. 在设备B（浏览器2或无痕模式）登录同一账号
4. 验证设置是否自动同步

**预期结果：**
- ✅ 设备B应显示与设备A相同的设置
- ✅ 设置修改应实时同步到服务器
- ✅ 登录时应自动拉取云端设置

### 场景2：阅读进度同步测试

**步骤：**
1. 在设备A上传一本电子书
2. 开始阅读，翻到第10页左右
3. 关闭阅读器（进度应自动保存）
4. 在设备B登录同一账号
5. 打开同一本书

**预期结果：**
- ✅ 设备B应自动跳转到设备A的阅读位置
- ✅ 阅读进度应每30秒自动保存
- ✅ 章节信息应正确同步

### 场景3：离线恢复同步测试

**步骤：**
1. 在设备A断网状态下修改设置
2. 继续阅读并翻页
3. 恢复网络连接
4. 在设备B验证数据同步

**预期结果：**
- ✅ 网络恢复后应自动同步离线期间的更改
- ✅ 不应丢失任何用户数据

### 场景4：并发修改冲突测试

**步骤：**
1. 在设备A和设备B同时登录
2. 同时修改相同的设置项
3. 观察冲突处理机制

**预期结果：**
- ✅ 应以最后修改时间为准
- ✅ 不应出现数据损坏

## 🐛 常见问题排查

### 问题1：设置不同步
**排查步骤：**
1. 检查网络连接
2. 查看浏览器控制台错误
3. 验证JWT token有效性
4. 检查后端日志

### 问题2：阅读进度丢失
**排查步骤：**
1. 检查数据库reading_progress表
2. 验证bookId传递是否正确
3. 查看自动保存定时器是否工作

### 问题3：登录后数据未加载
**排查步骤：**
1. 检查authStore.initializeUserData()调用
2. 验证API响应状态
3. 查看settingsStore初始化日志
